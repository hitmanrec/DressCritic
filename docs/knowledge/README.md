## Как читать и обновлять

- **confirmed** — наблюдалось в конкретном игровом захвате или другом указанном
  первичном источнике. Не означает доказательство для всех версий/сохранений.
- **implemented-unverified** — есть в коде, но нужное поведение в игре не доказано.
- **hypothesis** — объяснение, которое предстоит проверить.
- **unknown** — данных недостаточно. Отсутствие экспорта не превращается в ноль.
- **historical/superseded** — сохранённый результат старого подхода, не текущая инструкция.

Каждый новый вывод должен ссылаться на захват/коммит/код. При изменении вывода
сохранять старое доказательство и объяснять, что именно его заменило. Указывать
число наблюдавшихся примеров, а не объявлять решение универсальным по одному.
Не смешивать статус «собралось», «отрендерилось», «прошло JSON-проверку» и
«полезная/устойчивая оценка». Гипотезу не повышать до confirmed без проверки.

Приоритет документов: CURRENT для текущих действий; PRODUCT для продуктового
контракта; код/схемы для реализации; тематические страницы для сводных выводов;
старые отчёты для доказательств на дату их написания. Если они расходятся,
зафиксировать расхождение, а не переносить старую команду установки вслепую.

Оригиналы не перемещались и не переписывались. Некоторые поздние tar.xz были
переданы в чате и не включены в Git: реестр честно отмечает это. Не использовать
временные /tmp или пути вложений как постоянные ссылки. Скриншоты из чата сами
по себе не заменяют manifest и поля runtime. Полные игровые DLL/ассеты не добавлять.
