# Текущее состояние и очередь

Версия кода: **0.15.6**; последний полученный игровой пакет — **0.15.3**.

## UI по скриншотам 7 ноября — 0.15.6

Подтверждено визуально: теги WIP обрезаны по краям, их рамки не видно;
в истории карточка заказа узкая и текст перекрывает прищепка; требования занимают
только часть левой страницы; жюри на правой странице, но перелистывается правильно.

Исправления в коде (визуальная приёмка ещё нужна):

- Сторона страницы определяется по исходному Photo Mode, с fallback на исходную
  карточку задания. Поле leftPage задаёт размер листа, но больше не считается
  доказательством его стороны. Неоднозначная геометрия скрывает жюри с причиной.
- Карточка задания занимает 88% ширины листа сверху. Для title/body оставлен
  отступ справа 23% под прищепку; двойного уменьшения карточки и шрифта больше нет.
- Требования занимают 84% ширины выше жюри. Перемещается только точный
  oldQuestScoreDisplay целиком. Shared comissionScoreDisplay.inventoryRect не трогаем.
- Кнопки заимствуют Images, sliced sprite, декоративные слои, шрифт и состояния
  у Photo Mode. Слушатели и игровые скрипты не клонируются. Photo Mode не уменьшается.
- Для WIP tagMask добавлены отдельная рамка из native sliced sprite и запас
  отсечения по бокам. Размеры tagBarParent/строк/слайдеров не меняются. Padding и
  исходный stencil mask восстанавливаются при выходе; owned frame удаляется.
- Позиции, anchors, pivot, scale и размеры изменённых native rect восстанавливаются
  при смене платья и выходе из истории. Новые гербы из коммита 3c7b25b сохранены.

Проверка: обновить с закрытой игрой, установить. Сначала открыть WIP и список всех
тегов: рамка, целые звёзды и отступ справа от слайдеров; прокрутка работает. Затем
историю: карточка задания широкая без текста под прищепкой; требования шире и выше;
Rate/Houses/Order только слева, выглядят как Photo Mode. Проверить перелистывание,
возврат к WIP, Rate и scroll ремарок. При ошибке снять critic-export прямо на
проблемном экране: ui-layout.json теперь включает tagMask/tagBarParent, padding и
имена sprites. DLL игры в облаке отсутствуют, native сборка/внешний вид не подтверждены.

## Исторический заказ — продолжение 0.15.5

В пакете `230842` уже есть связь completedQuests[i].questDefinition: десять
именованных заказов и две записи Off rack dress с общим GUID
`33dec54894f06e245bb3006dfd0174c0`. Отсутствие этой связи в оценке было пробелом
интеграции, а не отсутствием runtime-данных.

Теперь история использует собственную запись: exact dress state reference,
questDefinition, budget, completionRequirements с focused tags, questGiverCharacter
и dressRecipient отдельно. `history-order.json` содержит данные и bounded graph;
активные заказы экспортируются отдельно как active-order.json/active-orders-raw.json.
OrderIndex не может подменить заказ исторического платья.

Классификация ограничена 11 наблюдавшимися GUID игры 0.7.0: десять commission и
один off-rack. Неизвестный GUID/версия/отсутствующее определение → unknown.
Название платья не является классификатором. Off-rack означает вид исходной
записи, но не доказательство факта продажи или её цены.

Справочник брифов ищется по историческому GUID/Unity asset key с прежними строгими
правилами: title-only не допускается к смысловой оценке. Жюри остаётся независимым.
Полные диалоги и вкусы получателя не выдумываются. Order tab показывает происхождение
после запуска оценки. Core-тесты проходят; native сборка и интеграция требуют игры.

Проверка: открыть Librarian Workwear и одно Off rack dress из истории, выполнить
Rate/critic-export для каждого. В первом пакете association должна ссылаться на
history record 0, во втором origin=off-rack и context stage skipped. Любой текущий
активный заказ не должен менять эти связи. Для нового GUID origin может оставаться
unknown; raw историческое определение сохранится для последующего подтверждения.

Цель релиза: самостоятельный полностью локальный мод; внешняя подготовка
ограничена скачиванием поддерживаемой vision-модели. Отзывы запускаются по запросу
из истории, UI встроен в блокнот, игра остаётся отзывчивой. Ручная установка,
настройка и запуск Ollama не отвечают цели релиза. Критерии приёмки:
[PRODUCT](../PRODUCT.md#product-goal-and-release-acceptance).

Порядок доведения до цели: принять UI и полноту fixed views на готовом платье;
выбрать и упаковать совместимый локальный inference runtime с управлением его
жизненным циклом; проверить offline-установку и измерить cold/warm latency.
Расширение брифов и профилей заказчиц не блокирует выпуск самостоятельного жюри
для платьев без заказа. Новые диагностические экраны для игрока не нужны.

## Результат аудита и продолжение 0.15.4

Сохранены history-only UI, гербы, Houses/Order, локализация и существующий
fixed-view pipeline. Изменения ниже требуют установки новой версии для проверки
в игре; их наличие в коде не означает визуальную приёмку.

- Пакет `20261104-230842-469-86722d39` целостен, но inference stage **failed**:
  модель вернула все remarks строками. В 0.15.4 только эта форма превращается в
  массив перед строгой валидацией. Оценки и текст не изменяются; raw сохраняется.
  Регрессия восстанавливает 6.5 / 7 / 5.5 / 7.5, среднее 6.625.
- Поздний ответ привязан к непрерывному просмотру конкретного state. Смена
  платья, выход/возврат или замена state отменяют его показ на странице.
- Контейнер жюри размещается по измеренным углам `leftPage` в координатах holder,
  вместо предположения о размерах holder. Если геометрия недоступна, UI скрывается
  с явной диагностической причиной. Сжатие игровых карточек ещё требует проверки.
- Исправлены scroll raycast, горизонтальные размеры строк, верхние якоря content
  и расчёт высоты текста через TMP. Layout больше не перестраивается каждый кадр.
- `ui-layout-original.json`, `ui-layout.json`, `ui-layout-after.json` сохраняют
  исходную/текущую геометрию, bindings, parents, screen corners и input/mask flags.
  Предел 192 узла, глубина 12; произвольные getters и UI-текст не экспортируются.
- Копии аксессуаров получают instance material property blocks и проверку
  трансформаций. Последний пакет содержит **0 аксессуаров**, поэтому не проверяет
  исправление декора. Добавлены ограничения количества копий и обходов.
- Старые captures не восстановлены: 13 необходимых тестам JSON сохранены отдельно
  в сжатых fixtures с исходными хешами; transport PNG синтетический.

Основные незакрытые блокеры: визуальная приёмка встроенного UI; покрытие декора
и постоянство цвета/света на украшенном платье; устойчивость и калибровка оценок;
проверка отдельного semantic context в игре и расширение sourced briefs; поставка
с автоматическим запуском локальной модели. Полные профили заказчиц и фактические
операции редактора пока не доказаны. Оценки требований игры остаются отдельной
незавершённой частью.

Следующий тест: закрыть игру, `git pull --ff-only`, `bash install.sh`; открыть
готовое украшенное платье в истории. Проверить четыре дома/гербы/ремарки и scroll.
Во время одной оценки переключить платье: старый результат не должен появиться
на новой странице. Затем оценить выбранное платье, выйти из истории и проверить
восстановление brief/stats/Photo. Снять два пакета одного украшенного платья при
разных поворотах viewer, импортировать `bash pull-exports.sh`. Если Rate недоступна,
использовать консоль `critic-export`: геометрия UI всё равно попадёт в пакет.

Ниже сохранён исходный план 0.15.3 как контекст аудита; приоритет имеет раздел выше.

## Как должно работать (целевой UX)

Только **просмотр платья из истории** (`oldDressViewHolder`):

1. Блок задания (title/text) — компактнее, выше, меньший body-шрифт.
2. Стат-полоски — сжаты и подняты.
3. Photo Mode — меньше и сдвинута.
4. В освободившемся месте **левой** страницы — упрощённый Jury **без** своего фона
   (фон = страница блокнота):
   - `Rate dress` + переключатель `Houses` / `Order`
   - после оценки: среднее, вердикт, **гербы домов** и **ремарки**
   - без закладки Jury, без оверлея, без времени снапшота, без limitations-текста
5. WIP / текущее платье — Jury **не** показывается.
6. Смена платья в истории сбрасывает результат.
7. UI-строки по умолчанию English; RU — опциональный
   `BepInEx/config/DressmakerCritic/locale.json` (образец `locale.example.ru.json`).

Пайплайн оценки (fixed views → local VLM jury) ранее давал оценки, но последний
пакет выявил также отказ валидации ответа. Проблема UI остаётся отдельной.

## Что не работает сейчас (подтверждено скринами)

Макет **всё ещё сломан** в истории:

- Элементы Jury (`Rate dress` / `Houses` / `Order`, иногда mean) собираются у
  **корешка** разворота, а не в нижней половине левой страницы.
- **Гербы и ремарки домов не видны** (есть место под лилией пустое) — контейнер
  Jury не получает нормальную высоту/ширину на левой странице, scroll с домами
  фактически не читаем.
- Сжатие brief/stats **недостаточное** или бьёт не в те RectTransform.

Гипотеза: `oldDressViewHolder` / система якорей Sketchbook не совпадает с
визуальной «левой страницей»; fractional anchors и scale существующих UI
элементов нестабильны. Нужна привязка к конкретному child (карточка статов /
parchment brief) через local offsets относительно **известного** RectTransform,
плюс dump иерархии в runtime для калибровки.
